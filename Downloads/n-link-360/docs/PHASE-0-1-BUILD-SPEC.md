# N-LINK 360 Phase 0-1 Implementation Specification

## Objective
Replace the rushed prototype behavior with a clean, responsive, role-based application foundation before expanding transaction modules.

## Authentication

- Login with secure authentication.
- Redirect user to their permitted workspace.
- No visible production role switcher.
- Session timeout and sign-out.
- Password reset.
- User status: active/inactive.

## Authorization

Authorization is permission based.

A user can have one primary role and additional explicit permissions. A role controls access to modules; work buttons control the functions available inside that workspace.

Example Factory In-Charge permissions:

- factory.production
- factory.qc
- factory.finished_goods
- inventory.factory_stock
- inventory.transfer
- inventory.returns
- inventory.damage
- reports.factory

Do not create separate employees merely because the system has multiple functions.

## Workspace Pattern

Every workspace follows:

1. Header with company logo, user name and notifications.
2. Short welcome/context line.
3. KPI strip relevant to the role.
4. Primary work buttons.
5. Recent activity.
6. Pending tasks/alerts.

No unnecessary menus for modules the user cannot access.

## Factory Workspace

One Factory In-Charge can access:

- Production Entry
- QC / Inspection
- Finished Goods Stock In
- Factory Stock
- Stock Transfer / Handover
- Returns
- Damage
- Daily Factory Report

Each is a work mode, not a separate employee role.

## Sales/Recovery Order Screen

This is a high-priority screen and must remain simple.

Top:

`Select Distributor / Dealer`

Then:

`Opening Balance | Recovery | Net Balance`

Then SKU entry table:

`SKU Name | Available Qty | Order Qty`

Display the first 10 quick-entry rows by default. Support search and additional rows for larger SKU masters.

Available Qty is read-only.

Order Qty is editable.

Do not require the Sales/Recovery person to type customer balance.

After order submit:

1. Validate customer.
2. Read current ledger balance.
3. Calculate net balance.
4. Validate requested quantity.
5. Run credit rule.
6. Create order.
7. Send for approval when required.
8. Never reduce inventory merely because an order is drafted.

## Acceptance Test

A Phase 0-1 build is accepted only if:

- A real user can log in.
- The user's permissions determine available modules.
- Factory In-Charge sees one Factory workspace with multiple work buttons.
- No unnecessary role-switching UI is exposed.
- Customer and SKU masters support unique simple IDs.
- The application is responsive.
- The company logo can be configured through the proper settings architecture.
- Existing prototype/mock data is not treated as production truth.
