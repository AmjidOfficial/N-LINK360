# N-LINK 360 P5 Order → Invoice Implementation Contract

## Objective
Connect the Sales/Recovery order to credit validation, stock validation, invoice posting, inventory stock-out and customer ledger in one controlled workflow.

## Lifecycle

`DRAFT → SUBMITTED → CREDIT_CHECK → APPROVED → INVOICED → DISPATCH_READY`

Alternative terminal states:

`REJECTED`, `CANCELLED`

## Order Submission

Sales/Recovery user selects Distributor/Dealer. The system reads the current ledger balance and inventory availability.

Show:

- Opening Balance
- Recovery posted/verified
- Net Outstanding
- Credit Limit
- Available Credit

Order lines:

- SKU
- Available Qty
- Order Qty
- Unit Price where permitted
- Line Total

Available Qty is read-only and server-authoritative.

Submitting a draft order does not change physical inventory or customer ledger.

## Credit Check

At submission/approval calculate:

`Projected Balance = Current Outstanding + Proposed Invoice Value`

Compare with customer credit limit and configured credit rules.

Possible outcomes:

- PASS
- REVIEW
- BLOCK

Blocked/review orders require authorized approval before invoicing.

## Stock Check

Before invoice posting, validate every SKU against current available stock.

If any line cannot be fulfilled, do not partially post the invoice unless a formal partial-invoice workflow is enabled.

## Approval

Authorized user can approve/reject/review.

Record:

- actor
- timestamp
- decision
- reason

## Invoice Posting

Invoice number is generated by the server.

Posting must be atomic:

1. Lock/revalidate required stock.
2. Confirm credit rule.
3. Create posted invoice.
4. Create invoice lines.
5. Create inventory OUT transaction for each SKU.
6. Update/derive inventory balance.
7. Create customer ledger DEBIT.
8. Link invoice to order.
9. Mark order INVOICED.
10. Make order available to Dispatch.

If any step fails, the complete database transaction must roll back.

## Invoice Data

- Invoice ID
- Invoice number
- Invoice date
- Customer ID
- Sales/Recovery employee
- Previous balance
- Invoice subtotal
- Discount
- Tax where applicable
- Net invoice amount
- New balance
- Payment terms
- Remarks

Invoice lines:

- SKU ID
- SKU code
- SKU name
- quantity
- unit price
- discount
- tax
- line amount

## Ledger

Invoice posting creates a customer debit.

Recovery creates a customer credit.

Balance is derived from posted ledger transactions, not manually edited from the invoice screen.

`New Balance = Previous Balance + Invoice Debit - Verified Recovery/Credits`

## Cancellation / Correction

Posted invoices cannot be silently edited or deleted.

Use:

- Cancellation with authorization
- Reversal transaction
- Credit note
- Debit note

Any reversal must preserve the original audit trail.

## Print

Posted invoice must support:

- Print preview
- Browser print
- PDF download

Use the shared company branding and invoice print settings defined in `docs/UI-RESPONSIVE-THEME-PRINTING.md`.

## Security

Client-side checks are for UX only. All credit, price, stock and posting checks must be repeated server-side/database-side.

## Acceptance Gate

P5 is complete only when a real approved order can be posted into a real invoice, stock decreases exactly once, customer ledger increases exactly once, invoice numbering is unique, the operation is auditable, and a printable/PDF invoice is generated from persisted data.
